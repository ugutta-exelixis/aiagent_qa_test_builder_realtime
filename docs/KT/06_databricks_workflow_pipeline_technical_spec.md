# Databricks Workflow/Pipeline - Technical Specification and KT Guide

## 1. Purpose
This document covers the Databricks job orchestration for source-notebook execution of Bronze, Silver, Gold, and pipeline summary.

Primary files:
- config/workflows/clinical_platform_pipeline_src.yaml
- dab/databricks.yml (canonical deploy definition)

## 2. Job Topology
Job name pattern:
- DDDA Clinical Platform Pipeline SRC [env]

Task order:
1. bronze_src
2. silver_src (depends on bronze_src)
3. gold_src (depends on silver_src)
4. pipeline_summary_src (depends on gold_src)

Execution semantics:
- max_concurrent_runs = 1
- each downstream task run_if = ALL_DONE in canonical bundle

## 3. Parameterization Model
Job-level parameters are declared once and mapped to notebook base_parameters.

Key parameter groups:
- storage: raw_bucket, stg_bucket, source_bucket
- catalogs/schemas: catalog, bronze_schema, silver_schema, gold_schema, metadata_catalog, registry_schema, metadata_schema
- runtime: environment, run_date
- silver controls: silver_mode/domain/entity/study_id/vendor/entity_workers/config_path
- gold controls: gold_mode/object_name/max_workers/config_path
- summary control: days
- governance: pii_unmask_group

## 4. Deployment Model (Asset Bundle)
Bundle features:
- sync.paths includes ../databricks_bundle so src notebooks are deployed with bundle.
- workspace root path is /Workspace/Shared/ddda-clinical-platform/${bundle.target}.
- run_as service principal is required via service_principal_client_id variable.
- existing_cluster_id is injected via bundle variable cluster_id.

## 5. Schedule and Permissions
Schedule (canonical job):
- Quartz cron: 0 30 11 * * ?
- Timezone: Asia/Kolkata

Permissions:
- users group has CAN_VIEW and CAN_MANAGE_RUN on job.

## 6. Operational Controls
Timeouts by layer (canonical):
- Bronze: 7200 sec
- Silver: 10800 sec
- Gold: 10800 sec
- Summary: 600 sec

Retry policy:
- max_retries: 0 (fail fast at task level, manual rerun strategy)

## 7. Promotion Across Environments
Targets defined:
- dev
- uat
- prod

Promotion behavior:
- Environment resolved through bundle target and variables.
- Same notebook code path promoted with environment-specific parameter values.

## 8. Failure and Recovery
Common workflow-level failures:
- Invalid notebook parameter mapping.
- Missing spark.conf required by notebooks.
- Incorrect existing_cluster_id or permissions.
- Missing synced notebook path in workspace.

Recovery steps:
1. Verify bundle validate output and resolved variables.
2. Confirm notebooks exist at ${workspace.file_path}/databricks_bundle/src.
3. Re-run failed task from Databricks UI with same parameters.
4. If metadata/dependency issue, fix upstream and rerun from affected layer.

## 9. KT Runbook
1. Validate bundle config and variable sources.
2. Deploy bundle to dev target.
3. Trigger manual run with controlled scope settings.
4. Confirm task DAG execution and outputs.
5. Validate alerts and metrics generated by each layer.

## 10. Handover Checklist
- Team can map job parameters to notebook widgets.
- Team can deploy and validate bundle per environment.
- Team can triage failures at task and config level.
- Team can adjust schedule, timeout, and governance parameters safely.
